# ADR-0007：序章动效画在独立的动效层上，时长读一份临时表

- 状态：提议
- 日期：2026-10-02

编号跳过 0006。旧的竖屏动效分支 `cursor/prologue-01-motion-3241` 用过 0006，那一版已被否决、不会合并，避免以后翻记录时混淆。

## 背景

序章第一关已经按 1920×1080 横屏重画（背景、灵梦立绘、界面框和几张光效图）。这一关要补上进关、放置、按钮、受击和结算的反馈，同时要守住：

- 不改玩法。`BattleSim` 的波次、费用、伤害和胜负一个数都不动，仍然只有灵梦能放。
- 反馈不能挡住残影要走的路线，也不能盖住顶栏的灵力、生命和波次数字，更不能吞掉点击。
- 只动已有的图（`yin_yang_gold.png`、`ofuda_ring.png` 等），不画新插画，不换背景和立绘。
- 动效师只给临时数字，正式时长和幅度归数值策划。
- 战斗光效要跟倍速走；界面动效（暗幕、栏、按钮、结算卡）按真实时间走，否则 ×2 时按钮手感会变。

## 决定

- 棋盘光效放在新节点 `BoardMotion`（`scripts/battle/board_motion.gd`）。它是 `BoardView` 的子节点，一样大，`mouse_filter` 为忽略。
  - 地面光效（点中格子时阴阳圈亮一下、放下灵梦时张开的结界圈）由 `BoardView` 在格子标记和角色之间调用 `draw_ground()` 画出，这样结界圈在灵梦脚下。
  - 盖章：`BoardView` 画灵梦时问 `BoardMotion.unit_scale()` 要倍数，先放大落下、压扁一点再弹回。
  - 小符纸取 `ofuda_ring.png` 正上方那一张，朝「离开路线」的方向飞出。
  - 受击溅小光点；打倒后光点（夹少量樱花瓣）飞到灵力数字下方就淡掉，不压数字；漏怪时守护点的阴阳阵泛红并裂开几道。
  - `battle_board.gd` 按「真实时间 × 倍速」推进它。
- 界面动效放在新节点 `ScreenMotion`（`scripts/battle/screen_motion.gd`），按真实时间推进：进关暗幕淡开、上下栏滑入；漏怪时生命数字左右抖；灵力光点到达时灵力数字亮一下；结算卡以顶上的阴阳印为轴从上往下展开。
- 结算卡后面的光点是 `ResultMotes`（`scripts/battle/result_motes.gd`）：守住了金色光点往上，失守了灰色光点往下。画在暗幕和卡片之间，不压字。
- 「开始」和「出击」挂 `PressMotion`（`scripts/ui/press_motion.gd`）：按下缩小，松开带一点回弹，按钮底图跟着一起缩放。标题画面等回弹播完再进关。
- 所有时长和幅度读 `data/prototype/ui_motion.json`，`meta.status` 是 `temporary`。读取由 `MotionConfig` 负责，缺字段时用脚本里的后备值。
- 生命数字放进一个普通的 `LifeSlot` 节点里再抖，这样抖动不会和顶栏的 `HBoxContainer` 排版互相覆盖。
- 动效节点都提供 `advance(delta)`，测试和截图脚本可以按固定步长推进，结果可重复。

这次故意不做：霞鹜文楷字体、金色大标题、三十个樱花粒子的完整一套（仍是 T-20）、音效、新的贴图和着色器。

## 后果

- 换背景或格子图时不用碰动效代码；调动效手感时只改一份 JSON。
- 测试 `tests/unit/test_battle_motion.gd` 会逐帧检查放置光效和路线的距离（`layout.route_clear_px`），以及灵力光点不进入顶栏数字的范围。以后换关卡或改格子位置，这两条测试会提醒动效是否压到路线。
- 代价是棋盘上多一个每帧重画的节点。现在光效只是几张小贴图、圆和线，开销很小；以后加大量粒子时要重新看一次手机上的性能。
- 结算卡的底色是一块 `StyleBoxFlat`，边框借用 `hud_frame.png` 的九宫格。T-20 统一主题时应把它并进全局主题，并另写 ADR。
