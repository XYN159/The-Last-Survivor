# ADR-0008：界面原画整张进游戏，用透明按钮串成占位流程

- 状态：提议
- 日期：2026-10-02

## 背景

原画分支 `cursor/ui-originals-84b6`（提交 `d070709`）画好了二十张 1920×1080 横屏界面原画：启动页、登录、服务器、公告、主界面、章节、关卡地图、关卡详情、编队、结算、剧情、角色列表、角色详情、升级、装备、抽卡、商店、任务、邮件、体力不足弹窗。所有者同意让它们进游戏。

这些图是整张画，不是切好的界面零件。按钮、文字和数字都画死在图上。同时要守住：

- 不改图的画面。
- 不改 `BattleSim` 的波次、费用、伤害和胜负，序章第一关仍然只有灵梦。
- 不做账号、密码、联网、存档、抽卡随机、商店扣钱、升级数值。这些画面只要能打开、看见、返回。
- 剧情页、关卡编号等图上的字只是原画内容，不当成设定。

## 决定

- 二十张图原样拷进 `assets/ui/originals/`，文件名不变。
- 新的启动场景 `scenes/main/original_flow.tscn`。它在窗口正中放一个 1920×1080 的舞台，每一屏把原画按原尺寸铺满舞台。窗口比 16:9 更宽或更高时，多出来的地方是深色底，原画和点击区不会错位。
- 能点的地方用透明按钮盖在原画上，只在按下时泛一层淡光。坐标、跳转和「返回」的位置都写在 `data/ui/original_screens.json`，由 `OriginalScreens` 读取。调点击位置不用改脚本。
- 原画上没画、但流程需要的入口，用半透明深底的小按钮补上，放在不挡主要画面的角落。文字走翻译 key（`ui.originals.*`）。
- 流程用一个简单的历史栈：进下一屏压栈，「返回」出栈；登录进主界面、结算回主界面时清空历史。体力弹窗盖在当前画面上，确认和取消都只是关掉。
- 「开始作战」先播一页剧情原画，点一下进现有的 `battle_board.tscn`。进战斗前一律关掉弹窗，体力弹窗不会拦住出击。
- 战斗结算卡保留「守住了 / 失守了」和「再打一次」；原来的「返回标题」改成「继续」，它通过 `original_flow.gd` 的静态变量 `pending_entry` 告诉流程先显示结算原画，确认后回主界面。
- 换页淡入时长放进 `data/prototype/ui_motion.json` 的 `originals.page_fade_sec`，和 ADR-0007 的动效表放在一起，仍是临时值。

这次故意不做：把原画切成可复用的界面零件、按钮按下的位移动效、读真实数据填进画面、旧标题场景 `main_menu.tscn` 的删除。

## 后果

- 所有者打开游戏就能按原画的顺序点一遍，并进入现在能玩的序章战斗。
- 图上的数字、角色和文字不会随游戏状态变化。以后真正做某个系统时，要把那一屏换成真正的界面节点，并从 `original_screens.json` 里拿掉对应的条目。
- 二十张 PNG 一共约 49 MB，安装包会明显变大。只在打开那一屏时加载，内存里同时最多两张（当前屏和弹窗）。正式界面做出来后应当删掉不用的原画。
- 测试 `tests/unit/test_original_flow.gd` 会检查二十张图都能装上且是 1920×1080，每个点击区都在画面内、指向存在的画面，登录不写文件，从主界面能一路走到战斗。
