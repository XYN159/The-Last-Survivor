# ADR-0002：GitHub Flow，只通过 PR 改 main

- 状态：已接受
- 日期：2026-09-25

## 背景

`main` 要始终对应一个能打开、CI 能打包的游戏。改动由 AI 写出、由仓库所有者阅读后合并。直接把提交推到 `main` 会让有问题的版本没有一个单独的审查页面，也没有 CI 工件可以下载试玩。

## 决定

- 采用 GitHub Flow。`main` 永远可发布。
- 所有改动使用 `feature/`、`fix/`、`chore/` 或 `docs/` 分支，通过 PR 进入 `main`。
- PR 标题使用英文 Conventional Commits，正文使用简体中文，并说明原因、验证步骤和界面截图。
- 合并前必须通过 CI：`lint`、`test`、`export-android`。
- 不在 `main` 上强推，也不删除 `main`。
- 撤回已合并的改动用新的 PR 执行 `git revert`，不用改写历史。
- 版本标签 `vX.Y.Z` 只打在已经位于 `main` 上的提交，用来触发 Release 工作流。
- 分支保护要在 GitHub 设置里打开才真正生效，步骤见 `docs/BRANCH_PROTECTION.md`。在保护打开之前，协作者和 AI 仍然必须遵守本决定，只是服务器还不会替你拒绝错误推送。

## 后果

- 每一次改动都有描述、检查记录和可下载的 APK。
- 很小的修改也要开 PR，比直接推送多一步。
- 所有者可以在没有第二位审查者的情况下合并，因此 PR 描述必须自己读得懂。不要开启「至少一人批准」，除非另外有人能点批准。
