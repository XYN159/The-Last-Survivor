# 0006 动效画在独立的覆盖层上，时长读临时表

## 状态

提议

## 背景

序章第一关要给进关、放置、按钮、受击、结算加反馈。同时有几件事要守住：

- 美术策划在另一条分支上换背景和格子图，`board_view.gd` 会被他们改。
- 动效师不定正式数字，时长和幅度要等数值策划（#8）定。
- 战斗特效要跟倍速走，界面动效不能跟倍速走，否则 ×2 时按钮手感会变。
- 规则（`BattleSim`）不能因为动效改变。

## 决定

- 棋盘上的动效画在新的 `BoardMotion` 节点上。它和 `BoardView` 一样大，叠在上面，不接收点击。`BoardView` 只多了两处：伤害数字的弹出和淡出，以及按 `BoardMotion` 给的倍率画角色大小。
- 界面动效（栏、符札、结算卡、暗幕）集中在 `ScreenMotion` 节点里，用 Tween，按真实时间走。按钮反馈是一个可以挂到任何按钮上的 `ButtonMotion`。
- 棋盘特效由 `battle_board.gd` 每帧按「真实时间 × 倍速」推进。
- 所有时长和幅度读 `data/prototype/ui_motion.json`，标为临时。和战斗手感有关、PR #4 已经定义过的字段（击杀光点、灵力栏弹跳、升级闪光）照抄进 `data/prototype/combat/feel.json`。
- 按钮和面板样式放在 `assets/themes/ofuda.tres`，只挂在关名符札和结算卡上，不替换全局 `AppTheme`。全局字体和主题等 T-20。

这次故意不做：音效、霞鹜文楷、金色标题、樱花粒子、真正的纹理特效。

## 后果

- 美术换背景、换格子图时，不用碰动效代码；动效换样子时也不用碰美术的画法。
- 数值策划定正式时长时只改一份 JSON。
- 代价是棋盘上多一个每帧重画的节点。现在特效都是圆和线，开销很小；以后换成纹理特效时要重新看一次性能。
- 结算卡和按钮现在有两套样式来源（全局 `AppTheme` 和 `ofuda.tres`）。T-20 合并主题时应该把它们并成一套，并新写一篇 ADR。
