# 路线图

顺序是固定的：先让工程可靠，再做单机核心循环，最后才考虑多人。每一项都应该是一个或几个小 PR，而不是一次做完。

## 0. 工程脚手架

就是当前这个阶段。

- Godot 4.7.2 工程能在编辑器里打开并运行标题画面。
- 格式检查、单元测试、调试 APK 都在 CI 里跑通。
- 文档和分支规则就位。你还需要按 `docs/BRANCH_PROTECTION.md` 在网页上打开保护。

## 1. 车道原型

- 角色在竖屏车道里自动向前。
- 能碰到至少一种门，小队人数按 `BalanceConfig` 变化。
- 人数在画面上能看出来。
- 还没有基地，打完或走到尽头就停住。

## 2. 一关能玩完

- 从标题或简单出击进入这一关。
- 有胜利和失败。
- 失败可以重开。
- 这一关的门的位置来自数据文件，不写死在脚本里。

## 3. 基地

- 一个基地场景，2 到 4 座建筑，具体名单以 `docs/GDD.md` 里你补上的内容为准。
- 用关卡给的资源升级。
- 升级能改变下一关的起始状态，例如起始人数。

## 4. 多关

- 关卡按顺序解锁。
- 后面的关更难，难度来自数据而不是复制一份脚本。
- 失败不抹掉已经升级的建筑。

## 5. 存档

- 退出再打开，建筑、资源和关卡进度还在。
- 使用 `SaveGame` 写到 `user://`。
- 存档带版本号，方便以后改字段。

## 6. 手感和数值

- 在真机上调整速度、碰撞和字号。
- 平衡只改 `data/balance/`。
- 补上你在 GDD 里标成「待你补充」的决定。

到这里，单机 MVP 就完整了。版本可以从 `0.x` 考虑进入 `1.0`。

## 7. 以后才做：多人

- 在你自己的 VPS 上跑一个保存进度的服务。
- 手机仍负责战斗演算，服务器接收 `SaveGame` 那种字典。
- 账号、匹配、实时同步都不在 MVP 里设计。真的要做时，先写一份新的架构决定记录，再开 PR。
