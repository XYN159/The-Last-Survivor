## 先看这几条（给不做美术的人）

1. **画风**：Q 版手绘平涂。大头小身，平涂颜色 + 一层简单阴影 + 描边。
2. **敌我一眼分清**：东方角色都是鲜艳的彩色；敌人「残影」一律是灰白、半透明、带褪色噪点的剪影。
3. **尺寸**：工程逻辑分辨率 1080×1920（见 `project.godot`）。棋盘 7 列 × 12 行，**每格 128 像素**，棋盘 896×1536，放在屏幕中间，左右各留 92 像素画装饰。所有图按显示尺寸的 **2 倍** 画，进游戏再缩小。
4. **动画**：角色用「拆件 + 骨骼 / 补间」做（头、身体、手、武器分开），尽量不画逐帧。
5. **程序不等美术**：开发前期全部用色块和简单图形占位，尺寸、锚点和最终图一致，换图不改代码。
6. **路线读得清**：角色只能放在预设空地上，一关可以有多条路线。路线、空地、障碍靠高度、边缘、纹理区分，多条路线靠入口形状（圆 / 三角 / 菱形 + 编号）和方向箭头区分，不只靠颜色。
7. **来源必须写清**：每一张图、每一个字体都要在 [CREDITS.md](CREDITS.md) 里登记来源和许可证。**不用任何官方游戏素材。**

## 待确认汇总

各文件末尾的「待确认」是完整版，这里只列标题：

1. 逻辑分辨率：按 `project.godot` 用 1080×1920，不用 720×1280（系统策划 / 程序）。
2. 「7 格铺满屏宽」做不到，采用每格 128 像素、左右留边（关卡策划 / 系统策划 / 程序）。
3. 更高的手机多出来的高度、刘海安全区怎么分（系统策划 / 程序）。
4. MVP 可玩角色：系统策划定为灵梦、魔理沙、琪露诺、八云紫；战斗、关卡、叙事的 PR 里琪露诺和紫的加入时机还没跟上（战斗策划 / 关卡策划 / 文案策划）。
5. MVP 残影：系统策划定为 2 种；关卡 PR #5 的第一章第 3 关数据里还有 3 只硬残影，战斗 PR #4 也把硬残影列为 MVP（关卡策划 / 战斗策划）。
6. 敌人、首领、角色的 ID，以及格子字符，在战斗和关卡两边不一致（战斗策划 / 关卡策划 / 程序）。
7. 首领琪露诺 2 个还是 3 个阶段，冰瀑是冰柱还是冰面（战斗策划 / 关卡策划）。
8. 「好位置」要不要在画面上标出来（关卡策划 / 系统策划）。
9. 放置操作是「拖头像」还是「点格子再点头像」（系统策划 / 文案策划）。
10. 符卡按钮放谁的符卡（系统策划 / 战斗策划）。
11. MVP 对话里的大妖精是否需要立绘（文案策划 / 制作人）。
12. 终章配色未单列（制作人）。
13. 工程默认纹理过滤和 mipmap 的项目设置（程序）。
14. 源文件（.kra / .psd）放哪、要不要加进 Git LFS（程序）。
15. 同一角色最多放几个，头像要不要显示数量（系统策划 / 战斗策划）。
16. 符卡名要不要换毛笔体（制作人）。
17. 三选一的稀有度分几档（系统策划）。
18. 星星解锁哪几种外观，MVP 先做哪 1–2 种（系统策划 / 制作人）。
19. 第一章首领是否仍为琪露诺（制作人 / 系统策划），首领相关资源在确认前只做占位。

画风本身不需要确认：制作人已经选定 Q 版手绘平涂。
