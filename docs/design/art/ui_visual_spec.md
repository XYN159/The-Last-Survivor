| 倍速 | 792, 1802, 240, 100 | 「1×」/「2×」切换 | PR #4 6.3（`×` 在字体里有，见第 4 节） |

- 底部栏底色和顶部栏相同，上边一条 4 像素朱红线。
- **长屏（已定，系统策划 2026-09-27）**：1080×1920 上底栏是 y 1676–1920，高 244。更长的手机先扣掉顶部刘海安全区：顶栏整块下移这段高度，棋盘仍从安全区之下开始，宽 896、高 1536，不跟着变高。扣完之后多出来的高度全部加给底栏，方便拇指点。上表的 y 是 1920 高时的位置。屏幕更高时，按钮改成相对屏幕底边定位，离底边的距离保持不变；多出来的高度留在棋盘和按钮之间。底栏上沿的朱红线仍贴着棋盘。
- **底栏背景要能纵向变高**。画一张九宫格：上下各留一条可延展的区域（纯色 `#1E1A24`，或很淡的竖向纹理，不要画会拉变形的花纹），左右边和四个角是固定装饰（朱红线、符纸角）。Godot 用 `NinePatchRect`，上下 `patch_margin` 盖住装饰，中间随高度拉伸。长屏上被拉高的是棋盘和按钮之间的那一段。角色头像、符卡按钮、叫波和倍速是叠在底图上的控件，不画进底图。可延展区里的淡纹理可以纵向平铺；四角不要平铺，否则接缝会错位。顶栏高度固定 140（再加上刘海安全区），不必为了长屏再拉高。
- 为什么不是一排：4 个 120 宽的头像加间隔要 528 像素，会压到符卡按钮；缩到一排 4 个 86 宽又太小不好点。2×2 每格 188×110，点击区够大。以后角色超过 4 名，角色栏改成左右翻页（每页 4 名，下方两个小圆点表示页数），尺寸不变。
- 放置操作：PR #4 是「点空格 → 点头像」，PR #2 教学文本写的是「拖动头像」。两种都要用到头像高亮和格子发光，美术资源相同，交互等待确认（待确认 9）。

### 2.1 三选一强化界面

GDD（PR #3）：每 5 波暂停一次，从 3 个强化里选 1 个，只在这一局有效。

| 部分 | 规格 |
| --- | --- |
| 背景 | 战斗画面暗化到 55%（和符卡演出的暗化一样，`feel.json` → `cutin.dim_alpha`），上方写「选择一项强化」，52 号字，带御币装饰 |
| 卡片 | 3 张，每张 **280×420**，横向排开，间隔 40（总宽 920，左右各留 80），竖直居中偏下（y 约 820–1240），手指好够 |
| 卡片造型 | 竖长符纸：和纸白底 `#F5EFE2`，外圈朱红细线（4 像素）；上方 128×128 图标区，中间强化名（40 号），下方一到两行说明（28 号，墨色）。MVP **不分稀有度**，不画普通 / 稀有 / 珍贵三档边框，也不用印章数量表示档次 |
| 三种状态 | 只靠颜色不够。每张卡左上角一个 64×64 角标，角标里同时有字和图标。已有层数写在角标旁边的小数字上（例如「1」） |
| 出现 | 3 张卡从下方依次翻起，每张间隔 0.08 秒，翻面 0.2 秒 |
| 选中 | 点一下放大到 105% 并加金色描边，再点一次（或点下方「确定」按钮）确认，避免误触；确认后另外两张淡出 0.15 秒，选中的卡飞向顶栏的强化小图标 |
| 已有强化 | 顶栏（y 0–140）右侧留一排 48×48 小图标显示本局已选强化，点开看说明。小图标沿用同一套角标，让玩家看出这张是新的、在叠，还是已经质变 |
| 素材 | 1 张卡底图 + 3 个角标（新 / 叠 / 变）+ 1 张质变卡框（含流光，或卡框与流光分开）+ 每个强化一张 128×128 图标。图标可以先用占位（符纸上写一个字） |

三种状态（已定，系统策划 2026-09-27）。质变门槛是**叠到 2 层**：这次选下去会从 1 层变成 2 层时，用「变」这张卡。

| 状态 | 什么时候用 | 角标（字 + 图标） | 卡框 |
| --- | --- | --- | --- |
| 新强化 | 本局还没有这项 | 字「新」+ 一张空白符纸图标 | 普通朱红细线 |
| 再叠一层 | 已经有了，但这次选完还不到 2 层 | 字「叠」+ 两张错开的符纸图标 | 普通朱红细线 |
| 这次会质变 | 这次选完会叠到 2 层 | 字「变」+ 一颗裂开的小星图标 | **显眼卡框**：外圈金色 `#D4A94F`、8 像素，外加一圈慢慢流动的金白流光。流光用序列帧或着色器，不要只靠把边框改成金色 |

- 弹出时机：每打完 5 波一次（GDD，PR #3；PR #4 `rules.json` 的 `buff_offers.every_n_waves_cleared` 也是 5）。最后一波打完不再弹出。2 倍速时，三选一和立绘演出都按真实时间播放（PR #4 `core_rules.md` 第 6 节边界表）。
- 强化只在本局有效，界面上不出现「永久」字样。
- 各有哪些强化、每一层的数值，归系统策划和数值策划。美术只做上面三种状态。

## 3. 和风装饰

装饰元素用于面板框、按钮和横幅，**全部自己画或用许可证写清楚的素材**，不照搬官方界面。

| 元素 | 用在 | 画法 |
| --- | --- | --- |
| 符纸（御札） | 面板、三选一卡片、对话框、暂停按钮 | 竖长或横长的和纸白底，朱红细边框，角上一个简单的红色印记（原创纹样，不写真实咒文） |
| 御币（纸垂） | 横幅两端、标题、选中状态 | 白色锯齿形纸条，挂在细木棍或绳上 |
| 注连绳 | 章节标题、胜利横幅 | 粗麻绳 + 纸垂 |
| 阴阳玉 | 读取中图标、灵梦相关按钮 | 通用的阴阳图形 |
| 结界纹 | 符卡按钮外圈 | 同心圆 + 细线，能量增长时逐段点亮 |

## 4. 字体

| 用途 | 字体 | 字号（1080 下） | 说明 |
| --- | --- | --- | --- |
| 所有界面文字 | Noto Sans SC Regular（仓库已有，`assets/fonts/NotoSansSC-Regular.ttf`，SIL OFL 1.1，许可证 `assets/fonts/OFL.txt`） | 正文 32（`app_theme.gd` 默认）；按钮 40；标题 52–64 | 就是思源黑体的同源字体（Noto Sans CJK / 思源黑体由 Google 和 Adobe 共同开发）。直接复用，不用再下载 |
| 伤害数字 | 同上 | 普通 34，重击 48 | PR #4 `feel.json` |
| 符卡名（立绘演出） | 同上，52 号，描边 | | 可选：以后换成 OFL 许可的毛笔体，见待确认 |

- 仓库里只有 Regular 一种字重。要强调时用字号、颜色、描边，不要用假粗体。
- 棋盘上和特效上的文字（伤害数字、「护甲」「无效」、横幅）一律加描边：描边 6 像素 `#2B2230`（Godot 的 `outline_size` 和 `font_outline_color`）。
- **字体里有什么、没有什么**（按 main 上的字体文件实测）：有基本拉丁、全部中日韩统一表意文字、中文标点 `，。！？：；、`、`「」『』《》（）……——`、以及 `×`（连击「×N」和倍速「2×」能显示，PR #4 `feedback.md` 担心的缺字问题不存在）。**没有 `★` `☆` `♪`**，所以星级必须用图片图标（`ui_icon_star_full.png` / `ui_icon_star_empty.png`），不能用文字星号。
- 新加任何字体，都要把许可证文件放在字体旁边，并在 [CREDITS.md](CREDITS.md) 登记。

## 5. 术语

界面上的文字按 PR #2 `glossary.md`：

- 说「角色」，不说「塔」；说「放置」，不说「建造 / 召唤 / 部署」。
- 说「守护点」，不说「基地 / 大本营 / 水晶」。
- 说「残影」，不说「怪物 / 敌军」；说「裂缝」，不说「传送门」。
- 说「路线」，不说「车道」。
- 符卡名写成 `符种「名字」`，例如 灵符「梦想封印」。
- 界面上首领战可以写「决斗」，不写「BOSS 战」。
