# 核心规则：格子、时间、局内流程、操作

> 状态：草案（战斗策划）。本文件是程序实现战斗循环的主依据。
> 数字标记：**【框架】** = 制作人已验收的框架，照做；**【草案默认值】** = 战斗策划给的规则或手感默认值，可调；**【数值·PR #8】** = 数值策划的字段，本文只写字段名，数字以 PR #8 为准。
> 对应配置：`data/balance/combat/rules.json`（规则和手感参数）。全部数值（血量、移速、攻击、费用、漏怪伤害、充能、倍率）只在数值策划 PR #8 的 `data/balance/combat/stats.json` 里（由 PR #8 的 CSV 生成），本 PR 不另存一份。写法 `stats.json` → `enemies.<id>.hp` 表示那张表里的字段路径。字段说明见 [data_reference.md](data_reference.md)。

## 1. 棋盘和坐标

### 1.1 格子

- 棋盘是 **7 列 × 12 行**【框架】。
- 坐标写成 `[col, row]`，原点在**左上角**：`col` 从左到右是 0–6，`row` 从上到下是 0–11。
- 残影从上方（小 `row`）出现，沿路线走向下方的守护点（大 `row`）。
- 所有距离、射程、速度都用「格」作单位。1 格 = 一个格子的边长。
- 位置用浮点数表示，格子 `[c, r]` 的中心点是 `(c + 0.5, r + 0.5)`。
- 射程是一组格子，再加上朝向（Q3b，2026-10-03）。不再用「以角色为圆心的圆形半径」。
- 范围记成以角色为原点的格子偏移。部署时选定的朝向把这组偏移转进棋盘：朝右保持 `(col, row)`，朝上换成 `(row, −col)`，朝下换成 `(−row, col)`，朝左换成 `(−col, −row)`。这里 `row` 向下为正。
- 每个人用哪一组合格子、站在地面还是高台、挡几个敌人，都还没定（待 P2）。本文只定「格子 + 朝向」。

### 1.2 格子类型

格子类型由关卡数据给出（关卡策划负责），战斗只认下面几种：

| 类型 | 含义 | 能放角色 | 敌人能走 |
| --- | --- | --- | --- |
| `path` | 路线格，地图里标成 `P` | 否 | 是 |
| `placeable` | 可放置格（预定槽位），地图里标成 `.`（教学里叫「发光的格子」） | 是 | 否 |
| `blocked` | 装饰或障碍（湖面、树） | 否 | 否 |
| `spawn` | 裂缝（出怪点），同时也是路线的第一格 | 否 | 是 |
| `guard` | 守护点所在格，是路线的最后一格 | 否 | 是（到达即结算） |

地形（冰面、浓雾、冰柱等）是叠在格子上的「地形效果」，不改变格子类型。对接方式见 [terrain_and_map.md](terrain_and_map.md)。

### 1.3 画面尺寸（需要确认）

- 工程逻辑分辨率是 1080×1920（`project.godot`）。如果 7 列铺满宽度，每格约 154 像素，12 行就要约 1851 像素，只剩约 70 像素给界面，放不下底部的符卡按钮和角色栏。
- 【草案默认值】每格 128 像素，棋盘 896×1536，左右各留 92 像素，顶部留 140 像素（时间、守护点生命、Boss 血条），底部留约 244 像素（灵力、角色栏、倍速）。更高的手机屏幕（`expand` 模式）多出来的高度加给底部栏。共用符卡按钮和叫波按钮都不再占这一栏（Q5、Q2）。
- 这是界面问题，最终由程序和制作人在真机上确认。配置里的字段是 `grid.cell_size_px` 和 `grid.board_offset_px`。

### 1.4 路线和「路程」

- 关卡数据给出每条路线的**格子序列**（从 `spawn` 到 `guard`，相邻两格必须上下或左右相邻）。
- 敌人沿「格子中心连线」移动。敌人的位置用 `path_progress`（已走过的格数，浮点）表示，0 = 裂缝格中心，`path_length` = 守护点格中心。
- **离守护点的路程** = `path_length - path_progress`。选敌、危急判定、紫的隙间换位都用这个值。
- 敌人所在的「行」= 它当前位置向下取整得到的 `row`。「最后 N 行」= `row ≥ 12 - N`。
- 一张地图可以有多条路线（多个裂缝）。路线在关卡数据里写死，这一关中途不变（`placement.routes_fixed_during_level`）。比较不同路线上的敌人时，只比较「离守护点的路程」。

## 2. 时间和 tick

### 2.1 固定 60Hz 逻辑

- 战斗逻辑以**固定 60Hz** 的 tick 运行，每 tick 逻辑时长 `dt = 1/60 秒`【草案默认值，来自战斗策划决定 1】。
- 演出（闪白、飘字、震屏、光点）不影响逻辑结果。例外只有两个：**慢动作**（逻辑变慢）和**立绘演出**（逻辑暂停）。
- 仍需要随机的逻辑（例如冻结几率）来自**每局一个种子**的随机数生成器，方便测试复现。通用暴击已去掉，见 damage_and_status.md。主线不再抽三选一。

### 2.2 时间倍率怎么实现（给程序）

不要用 `Engine.time_scale` 驱动逻辑：它会改变每个物理帧的 `delta`，导致「每 tick 固定 1/60 秒」失效。建议做法：

1. 战斗自己维护一个累加器 `logic_accumulator`。
2. 每个物理帧：`logic_accumulator += 真实帧时长 × 总倍率`。
3. `总倍率 = 倍速（1 或 2） × 慢动作倍率（平时 1，慢动作 0.3） × 暂停（技能立绘、菜单时为 0）`。主线不再为三选一暂停。
4. 当 `logic_accumulator ≥ 1/60` 时执行一次 tick 并减去 1/60，最多连续执行 `tick.max_ticks_per_frame = 4` 次，防止卡顿后雪崩。
5. 演出层（动画、粒子、飘字）用真实时间 × 倍速播放，不跟随慢动作以外的逻辑暂停。

所以 2 倍速 = 每帧跑 2 个 tick；慢动作 + 2 倍速 = 2 × 0.3 = 0.6 倍【框架：慢动作倍率与 2 倍速相乘】。

### 2.3 每 tick 结算顺序【战斗策划决定 1】

每个 tick 严格按下面 12 步执行。同一步里有多个对象时，按「生成顺序（实例 ID 从小到大）」处理，保证结果可复现。

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| ① | 处理玩家指令 | 放置、选方向、撤退、再部署、放该角色自己的技能。没有局内升级，没有卖出，没有叫下一波，没有共用符卡条。指令在输入时进队列，这一步统一执行。 |
| ② | 时间轴与刷怪 | 推进连续时间轴（第 4 节），把到时刻的敌人放到裂缝格。新出生的敌人本 tick 不移动。 |
| ③ | 状态计时更新和到期移除 | 所有敌人和角色身上的状态时长减 `dt`，到期的移除并触发 `on_end_apply`（比如冻结结束给冻结免疫）。持续伤害（灼烧）的跳伤也在这一步产生「命中请求」，放到第 ⑧ 步结算。 |
| ④ | 地形效果计算 | 地形计时、生成和消失；区域类地形（结界、火焰地面）检查敌人进出，挂上或移除状态；算出每个敌人本 tick 所在格子的移动倍率。 |
| ⑤ | 敌人移动 | 按第 3.2 节公式推进 `path_progress`。走到 `path_length` 的敌人标记为「到达中」（`reaching`），但**本 tick 仍然可以被攻击**，第 ⑩ 步才结算。 |
| ⑥ | 角色选敌、攻击冷却 | 冷却减 `dt`；冷却好且射程内有目标就攻击：即时命中类（魔理沙直线、紫的隙间、近战）直接生成「命中请求」；弹体类生成弹体。自动技能（灵梦结界、琪露诺冻结、紫的隙间换位）也在这一步按冷却触发。 |
| ⑦ | 弹体移动与命中检测 | 移动弹体，检测碰撞，碰到就生成「命中请求」。直线类攻击在这一步检查冰柱遮挡。 |
| ⑧ | 逐次命中结算 | 按生成顺序逐个执行伤害流水线（见 [damage_and_status.md](damage_and_status.md)）。一个敌人血量归零后，本 tick 后续打到它的命中请求作废（弹体按各自规则转向或消失）。 |
| ⑨ | 死亡处理 | 记连击、触发死亡相关效果。主线不再因击杀给共用符卡条充能（Q5）。每人技力怎么回复待 P2，这里不另定。 |
| ⑩ | 到达守护点结算 | 对仍处于「到达中」且未死亡的敌人：守护点扣命，敌人移除。Boss 漏过扣 2 命（Q4）。旧稿里的折返待 P4，不当已定。 |
| ⑪ | 胜负判定 | 见第 5 节。 |
| ⑫ | 反馈事件入队 | 把本 tick 产生的所有反馈事件（闪白、飘字、光点、震屏、连击、报警等）交给演出队列。演出层按 [feedback.md](feedback.md) 的节流和上限规则播放。 |

**这个顺序带来的效果（程序要保证）**：

- 敌人在第 ⑤ 步踩进守护点，如果第 ⑥–⑧ 步被打死，就不扣守护点的血。这是「险胜」手感的来源。
- 同一 tick 里先结算伤害（⑧），后结算死亡（⑨），再结算漏怪（⑩），最后判胜负（⑪）。

## 3. 敌人移动

### 3.1 基础速度

每种敌人的基础移速（格/秒）是 `stats.json` → `enemies.<id>.move_speed_cells_per_sec`。Boss 在 `bosses` 段：冰之残影是 `bosses.boss_cirno.move_speed_cells_per_sec`（用户已确认 0.4）。【数值·PR #8】

### 3.2 每 tick 的移动公式

1. 如果敌人身上有任何「硬停止」状态（`st_freeze`、`st_time_stop`、`st_hold`、`st_gap_daze`），本 tick 速度为 0。
2. 否则：
   - `减速倍率 = 1 - 最强的一个 st_slow 的强度`（减速不叠加，只取最强）。
   - `地形倍率 =` 敌人当前所在格子上「移动类地形」的倍率（冰面是 `terrain.ter_ice.move_speed_mult`；没有地形就是 1.0；多个移动类地形重叠时取优先级最高的一个）。
   - `总倍率 = 减速倍率 × 地形倍率`，再限制在 `[下限, 2.0]` 之间。下限：普通敌人 0.3【框架：移动速度总倍率下限 30%】，Boss 0.5【草案默认值】。
3. `path_progress += 基础速度 × 总倍率 × dt`。

例子：快残影被琪露诺普攻减速（强度 `characters.chr_cirno.normal_effect.value`，记作 s），又踩在冰面上（倍率记作 m）：速度 = `enemies.enm_shade_fast.move_speed_cells_per_sec` × (1 − s) × m。小残影吃到上限强度的减速（`statuses.st_slow.max_strength`）时，总倍率低于 0.3 就按 0.3 算。

### 3.3 击退

- 击退 = 把 `path_progress` 往回减，默认每次命中 0.1 格【框架】。
- 同一个敌人 0.25 秒内只吃一次普通击退【草案默认值】，防止高攻速角色把敌人钉死。技能标明的大击退（彩光乱舞）不受这个冷却限制。
- 硬残影有 50% 击退抗性（击退距离 × 0.5）。
- 冻结、时停中的敌人和 Boss 不被击退。
- 击退不会把 `path_progress` 减到 0 以下。
- 「到达中」的敌人被击退到 `path_length` 以下时，取消「到达中」标记。

## 4. 局内状态机和出怪时间轴

> 2026-10-03 用户拍板 Q2：改用连续时间轴，取代「布阵 10 秒、每波刷 20 秒、再空 4 秒」这套波次钟。旧的 `deploy` / `spawning` / `intermission`、叫下一波，都不再当规则。

### 4.1 局内状态

关卡开始后，逻辑时间从 0 往前走。出怪不靠「这一波结束才放下一波」。

| 状态 | 进入条件 | 期间允许的操作 | 退出条件 |
| --- | --- | --- | --- |
| `running` 战斗进行 | 关卡载入完成，时间轴开始走 | 放置（点格子 → 点头像 → 选方向）、撤退、再部署、放自己的技能。没有局内升级，没有共用符卡按钮，没有叫下一波 | 时间轴上安排的敌人都已出生，场上还有人 → `clearing` |
| `clearing` 收尾 | 时间轴上的出怪都已触发，场上还有敌人 | 同上 | 场上清空且守护点生命 > 0 → `victory`。Boss 关还要等 Boss 被击败 |
| `victory` 胜利 | 见第 5 节 | 无 | 进入结算界面 |
| `defeat` 失败 | 守护点生命归零 | 无 | 失败界面。可以整关重打。旧的「从当前波重来」属于波次钟，Q2 之后不再当规则 |

逻辑暂停只在这些时候发生：角色技能若带立绘演出、Boss 换阶段的立绘、暂停菜单、教学等玩家操作。主线没有强化三选一（Q12），不再为此暂停。

### 4.2 连续时间轴（Q2）

出怪写成一条从关卡开始起算的时间轴。每个条目自己带时刻、敌人、路线、数量和间隔。时间走到那一刻就出生。

1. 不再有「每波 20 秒刷怪窗口，窗口结束再空 4 秒」。`duration_sec`、`intermission_sec`、`waves[].delay_sec` 是旧波次钟的字段，不当现在的规则。
2. 不再有「第一波不读 delay」或「第一波必须写成 0」这种特判。第一只什么时候出，看时间轴上它的时刻。
3. 不再有单独的空档状态，也没有「清场就缩短空档」。中间空多久，写在时间轴上。
4. 叫下一波，包括 D-18「刷怪窗口里也能叫，没出生的怪照常出」，属于旧波次钟。Q2 之后不再当规则。用户没有拍 D-18。
5. 关卡表怎么把旧波次改成时间轴，归关卡策划。战斗只按时刻出生，不在这里另定一套秒数。

Boss 按这条时间轴出场（Q4）。漏到守护点扣 2 命。Boss 的阶段和手法见 enemies_and_bosses.md，细则待 P4。

### 4.3 节奏

旧稿用「每波约 24 秒、10 波约 4 分钟」估时长。那是波次钟，Q2 之后不再用来排关。一关多长、中间空多久，写在该关的时间轴里。序章和第一章有几关，仍以关卡策划 PR #5 的关卡名单为准，不再在这里用波数换算分钟。

## 5. 守护点、胜负

### 5.1 守护点

- 守护点有生命值 `stats.json` → `guard.max_hp`【数值·PR #8】。叙事上叫守护点的「颜色」（PR #2 术语表，系统名待系统策划定）。
- 普通敌人到达守护点，扣 `enemies.<id>.leak_damage`【数值·PR #8】。
- Boss 漏过扣 **2 命**（Q4，2026-10-03 已定）。每漏过一次扣 2，不在本文另写别的扣命数字。旧稿「读 `bosses.<id>.leak_damage` 然后回裂缝再走」里的折返，不当用户已经同意，见 enemies_and_bosses.md。
- 慧音的「隐史」给守护点加护盾层，每层抵消一次漏怪（见 characters.md）。
- **报警**：任一敌人进入最后 2 行（`row ≥ 10`）时，守护点闪红光并播报警音【框架】。报警音 2 秒（真实时间）内最多响一次；只要最后 2 行有敌人，守护点就持续红光脉冲【草案默认值】。
- **扣血反馈**：守护点每次扣血，屏幕边缘泛红 0.4 秒【框架】；0.4 秒内再次扣血就重置计时，不叠加亮度。

### 5.2 胜负【战斗策划决定 5】

- **失败**：守护点生命 ≤ 0（制作人说的「基地」就是这里的守护点）。第 ⑩ 步扣到 0 以后，第 ⑪ 步立刻判负，同一 tick 其他事件不再有意义。
- 同一 tick 既满足胜利又满足失败时，判失败。
- **普通关胜利**：时间轴上的出怪都已触发，场上没有任何敌人，并且守护点生命 > 0。
- **Boss 关**（Q4，2026-10-03）：Boss 按时间轴出场。漏过扣 2 命。这一关要等 Boss 被击败，并且场上其他敌人也清空，才算打完。折返和三阶段是旧稿，待 P4。
- **输了之后**：可以整关重打。旧的「从当前波重来」和下面这张快照表属于波次钟，Q2 之后不再当规则，只留着对照：

| 恢复 | 不恢复 |
| --- | --- |
| 守护点生命、灵力、已放角色（格子、等级）、强化层数、符卡能量、当前符卡使、场上残存的敌人（含 Boss 的血量、阶段、位置）、地形、波次计时、随机数状态 | 连击数（归 0）、已发现的联动（发现过就不收回）、教学进度 |

  「这一波开始那一刻」= 这一波第一只出生前。因为不等清场，上一波留下的敌人也在快照里。Boss 关从 Boss 波重来时，Boss 回到这一波开始时的血量和阶段（一般是满血第 1 阶段）。

## 6. 操作（竖屏单手）

### 6.1 放置

1. 只能放在地图里标成 `.` 的格子上。路线格标成 `P`，不能放。
2. 顺序是：先点空的 `.` 格，再点角色头像，再选方向（Q3b，2026-10-03）。选完方向才算放下，然后播放落地动画。
3. 点别处取消。还没选方向之前，角色不在格子上。
4. 同一个角色只能部署一个（Q3）。旧的「最多 3 个、第 k 个费用递增」作废。`max_copies`、`copy_cost_increase_ratio` 不再当放置规则。
5. 美铃不是 MVP 角色。PR #15 曾把「美铃必须紧贴路线」写成 D-19 已定，用户没有拍这条，不当规则。她挡几个人、站哪一种格子，待 P2。

### 6.2 已放置的角色

点已放置的角色：按她的朝向亮出射程格子，并给出「撤退」。没有「升级」，也没有「设为符卡使」。

- 局内升级删除（Q6，2026-10-03）。成长在局外。局内不再花灵力升到 2 级、3 级，也不再按 `upgrade_costs`、`level_attack_mult` 在战斗里变强。
- 要换位置或换朝向：先撤退，再按 6.1 重新部署。撤退和再部署的等待、费用加层、返还比例待 P6，本文不定这些数字，也不把旧的「卖出返还 70%」写成新规则。
- 被冻住时能不能点冰块提前解开，属于 D-05。用户没有拍 D-05，不当已定。

## 7. 边界情况汇总

| 情况 | 处理 |
| --- | --- |
| 敌人刚出生 | 出生状态 0.3 秒【草案默认值】：不移动、不可被选为目标，防止还没看见就被秒。 |
| 射程内没有敌人 | 冷却停在「就绪」，敌人一进射程立即攻击。 |
| 目标在弹体飞行中死亡 | 追踪弹在 `retarget_radius_cells` 内换最近的新目标；没有就直线飞完寿命后消失。非追踪弹继续直飞，可以打中路过的敌人。 |
| 攻击者在弹体飞行中撤退 | 已发出的弹体照常结算，仍算那个角色的攻击（联动照样生效）。弹体生成时记下 `attacker_character_id`。 |
| 立绘演出期间有输入 | 点击只用来跳过演出，不执行放置等指令。 |
| 两个立绘演出在同一 tick 被触发 | 按触发顺序排队播放：角色技能（第 ① 步）在前，Boss 换阶段（第 ⑧ 步）在后。 |
| 慢动作期间又满足慢动作条件 | 不重新触发（有 8 秒冷却）。 |
| 叫波、刷怪窗口里叫波、空档缩短 | 旧波次钟。Q2 之后不再当规则。D-18 用户没有拍。 |
| 2 倍速下的立绘演出 | 不受倍速影响（按真实时间播放）。主线不再为三选一暂停（Q12）。 |
