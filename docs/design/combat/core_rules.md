# 核心规则：格子、时间、局内流程、操作

> 状态：草案（战斗策划）。本文件是程序实现战斗循环的主依据。
> 数字标记：**【框架】** = 制作人已验收的框架，照做；**【草案默认值】** = 战斗策划给的规则或手感默认值，可调；**【数值·PR #8】** = 数值策划的字段，本文只写字段名，数字以 PR #8 为准。
> 对应配置：`data/balance/combat/rules.json`（规则和手感参数）。全部数值（血量、移速、攻击、费用、漏怪伤害、充能、倍率）只在数值策划 PR #8 的 `data/balance/combat/stats.json` 里（由 PR #8 的 CSV 生成），本 PR 不另存一份。写法 `stats.json` → `enemies.<id>.hp` 表示那张表里的字段路径。字段说明见 [data_reference.md](data_reference.md)。

## 1. 棋盘和坐标

### 1.1 格子

- 棋盘是 **7 列 × 12 行**【框架】。
- 坐标写成 `[col, row]`，原点在**左上角**：`col` 从左到右是 0–6，`row` 从上到下是 0–11。
- 残影从上方（小 `row`）出现，沿路线走向下方的守护点（大 `row`）。
- 所有距离、射程、速度都用「格」作单位。1 格 = 一个格子的边长。
- 位置用浮点数表示，格子 `[c, r]` 的中心点是 `(c + 0.5, r + 0.5)`。
- 射程判定用**圆形**：角色格子中心到敌人当前位置的直线距离 ≤ 射程格数，就算在射程内。

### 1.2 格子类型

格子类型由关卡数据给出（关卡策划负责），战斗只认下面几种：

| 类型 | 含义 | 能放角色 | 敌人能走 |
| --- | --- | --- | --- |
| `path` | 路线格，地图里标成 `P` | 否 | 是 |
| `placeable` | 可放置格（预定槽位），地图里标成 `.`（教学里叫「发光的格子」） | 是 | 否 |
| `blocked` | 装饰或障碍（湖面、树） | 否 | 否 |
| `spawn` | 裂缝（出怪点），同时也是路线的第一格 | 否 | 是 |
| `guard` | 守护点所在格，是路线的最后一格 | 否 | 是（到达即结算） |

地形（冰面、浓雾、冰柱等）是叠在格子上的「地形效果」，不改变格子类型。对接方式见 [terrain_and_map.md](terrain_and_map.md)。

### 1.3 画面尺寸（需要确认）

- 工程逻辑分辨率是 1080×1920（`project.godot`）。如果 7 列铺满宽度，每格约 154 像素，12 行就要约 1851 像素，只剩约 70 像素给界面，放不下底部的符卡按钮和角色栏。
- 【草案默认值】每格 128 像素，棋盘 896×1536，左右各留 92 像素，顶部留 140 像素（波次、守护点生命、Boss 血条），底部留约 244 像素（灵力、符卡按钮、倍速、叫波）。更高的手机屏幕（`expand` 模式）多出来的高度加给底部栏。
- 这是界面问题，最终由程序和制作人在真机上确认。配置里的字段是 `grid.cell_size_px` 和 `grid.board_offset_px`。

### 1.4 路线和「路程」

- 关卡数据给出每条路线的**格子序列**（从 `spawn` 到 `guard`，相邻两格必须上下或左右相邻）。
- 敌人沿「格子中心连线」移动。敌人的位置用 `path_progress`（已走过的格数，浮点）表示，0 = 裂缝格中心，`path_length` = 守护点格中心。
- **离守护点的路程** = `path_length - path_progress`。选敌、危急判定、紫的隙间换位都用这个值。
- 敌人所在的「行」= 它当前位置向下取整得到的 `row`。「最后 N 行」= `row ≥ 12 - N`。
- 一张地图可以有多条路线（多个裂缝）。路线在关卡数据里写死，这一关中途不变（`placement.routes_fixed_during_level`）。比较不同路线上的敌人时，只比较「离守护点的路程」。

## 2. 时间和 tick

### 2.1 固定 60Hz 逻辑

- 战斗逻辑以**固定 60Hz** 的 tick 运行，每 tick 逻辑时长 `dt = 1/60 秒`【草案默认值，来自战斗策划决定 1】。
- 演出（闪白、飘字、震屏、光点）不影响逻辑结果。例外只有两个：**慢动作**（逻辑变慢）和**立绘演出**（逻辑暂停）。
- 所有逻辑用的随机数（暴击、冻结几率、强化抽选）来自**每局一个种子**的随机数生成器，方便测试复现。

### 2.2 时间倍率怎么实现（给程序）

不要用 `Engine.time_scale` 驱动逻辑：它会改变每个物理帧的 `delta`，导致「每 tick 固定 1/60 秒」失效。建议做法：

1. 战斗自己维护一个累加器 `logic_accumulator`。
2. 每个物理帧：`logic_accumulator += 真实帧时长 × 总倍率`。
3. `总倍率 = 倍速（1 或 2） × 慢动作倍率（平时 1，慢动作 0.3） × 暂停（立绘演出、强化三选一、菜单时为 0）`。
4. 当 `logic_accumulator ≥ 1/60` 时执行一次 tick 并减去 1/60，最多连续执行 `tick.max_ticks_per_frame = 4` 次，防止卡顿后雪崩。
5. 演出层（动画、粒子、飘字）用真实时间 × 倍速播放，不跟随慢动作以外的逻辑暂停。

所以 2 倍速 = 每帧跑 2 个 tick；慢动作 + 2 倍速 = 2 × 0.3 = 0.6 倍【框架：慢动作倍率与 2 倍速相乘】。

### 2.3 每 tick 结算顺序【战斗策划决定 1】

每个 tick 严格按下面 12 步执行。同一步里有多个对象时，按「生成顺序（实例 ID 从小到大）」处理，保证结果可复现。

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| ① | 处理玩家指令 | 放置、升级、卖出、释放符卡、叫下一波、开关自动释放。指令在输入时进队列，这一步统一执行。自动释放符卡的判定也在这一步。 |
| ② | 波次计时与刷怪 | 推进波次状态机（第 4 节），把到时间的敌人放到裂缝格。新出生的敌人本 tick 不移动。 |
| ③ | 状态计时更新和到期移除 | 所有敌人和角色身上的状态时长减 `dt`，到期的移除并触发 `on_end_apply`（比如冻结结束给冻结免疫）。持续伤害（灼烧）的跳伤也在这一步产生「命中请求」，放到第 ⑧ 步结算。 |
| ④ | 地形效果计算 | 地形计时、生成和消失；区域类地形（结界、火焰地面）检查敌人进出，挂上或移除状态；算出每个敌人本 tick 所在格子的移动倍率。 |
| ⑤ | 敌人移动 | 按第 3.2 节公式推进 `path_progress`。走到 `path_length` 的敌人标记为「到达中」（`reaching`），但**本 tick 仍然可以被攻击**，第 ⑩ 步才结算。 |
| ⑥ | 角色选敌、攻击冷却 | 冷却减 `dt`；冷却好且射程内有目标就攻击：即时命中类（魔理沙直线、紫的隙间、近战）直接生成「命中请求」；弹体类生成弹体。自动技能（灵梦结界、琪露诺冻结、紫的隙间换位）也在这一步按冷却触发。 |
| ⑦ | 弹体移动与命中检测 | 移动弹体，检测碰撞，碰到就生成「命中请求」。直线类攻击在这一步检查冰柱遮挡。 |
| ⑧ | 逐次命中结算 | 按生成顺序逐个执行伤害流水线（见 [damage_and_status.md](damage_and_status.md)）。一个敌人血量归零后，本 tick 后续打到它的命中请求作废（弹体按各自规则转向或消失）。 |
| ⑨ | 死亡处理 | 发灵力、记连击、加符卡能量（击杀部分）、触发死亡相关效果（强化「青蛙冰雕」、忘的「登记」等）。 |
| ⑩ | 到达守护点结算 | 对仍处于「到达中」且未死亡的敌人：守护点扣「漏怪伤害」，敌人移除（Boss 按自己的规则折返）。 |
| ⑪ | 胜负判定 | 见第 5 节。 |
| ⑫ | 反馈事件入队 | 把本 tick 产生的所有反馈事件（闪白、飘字、光点、震屏、连击、报警等）交给演出队列。演出层按 [feedback.md](feedback.md) 的节流和上限规则播放。 |

**这个顺序带来的效果（程序要保证）**：

- 敌人在第 ⑤ 步踩进守护点，如果第 ⑥–⑧ 步被打死，就不扣守护点的血。这是「险胜」手感的来源。
- 同一 tick 里先结算伤害（⑧），后结算死亡（⑨），再结算漏怪（⑩），最后判胜负（⑪）。

## 3. 敌人移动

### 3.1 基础速度

每种敌人的基础移速（格/秒）是 `stats.json` → `enemies.<id>.move_speed_cells_per_sec`。Boss 在 `bosses` 段：冰之残影是 `bosses.boss_cirno.move_speed_cells_per_sec`（用户已确认 0.4）。【数值·PR #8】

### 3.2 每 tick 的移动公式

1. 如果敌人身上有任何「硬停止」状态（`st_freeze`、`st_time_stop`、`st_hold`、`st_gap_daze`），本 tick 速度为 0。
2. 否则：
   - `减速倍率 = 1 - 最强的一个 st_slow 的强度`（减速不叠加，只取最强）。
   - `地形倍率 =` 敌人当前所在格子上「移动类地形」的倍率（冰面是 `terrain.ter_ice.move_speed_mult`；没有地形就是 1.0；多个移动类地形重叠时取优先级最高的一个）。
   - `总倍率 = 减速倍率 × 地形倍率`，再限制在 `[下限, 2.0]` 之间。下限：普通敌人 0.3【框架：移动速度总倍率下限 30%】，Boss 0.5【草案默认值】。
3. `path_progress += 基础速度 × 总倍率 × dt`。

例子：快残影被琪露诺普攻减速（强度 `characters.chr_cirno.normal_effect.value`，记作 s），又踩在冰面上（倍率记作 m）：速度 = `enemies.enm_shade_fast.move_speed_cells_per_sec` × (1 − s) × m。小残影吃到上限强度的减速（`statuses.st_slow.max_strength`）时，总倍率低于 0.3 就按 0.3 算。

### 3.3 击退

- 击退 = 把 `path_progress` 往回减，默认每次命中 0.1 格【框架】。
- 同一个敌人 0.25 秒内只吃一次普通击退【草案默认值】，防止高攻速角色把敌人钉死。技能标明的大击退（彩光乱舞）不受这个冷却限制。
- 硬残影有 50% 击退抗性（击退距离 × 0.5）。
- 冻结、时停中的敌人和 Boss 不被击退。
- 击退不会把 `path_progress` 减到 0 以下。
- 「到达中」的敌人被击退到 `path_length` 以下时，取消「到达中」标记。

## 4. 局内状态机和波次

### 4.1 局内状态

| 状态 | 进入条件 | 期间允许的操作 | 退出条件 |
| --- | --- | --- | --- |
| `deploy` 布阵期 | 关卡载入完成 | 放置、升级、卖出、设为符卡使、「开始」按钮 | 倒计时 `deploy_time_sec`（10 秒）走完，或玩家点「开始」。序章开 `deploy_wait_for_player` 时，玩家放下第一个角色前倒计时不走 |
| `spawning` 刷怪窗口 | 某一波开始。第一只在窗口开始时出生 | 放置、升级、卖出、放符卡；**不能换符卡使**；可以叫下一波（见 4.2） | 这一波的刷怪窗口（20 秒，`duration_sec`）走完 → `intermission`；或玩家叫波 → 下一波 `spawning`（这一波没出生的敌人照常出生） |
| `intermission` 空档 | 这一波的 20 秒刷怪窗口结束 | 所有操作，包括换符卡使；可以叫下一波（跳过剩下的空档）；第 5、10、15 波进入空档时弹出强化三选一 | 空档固定 `intermission_sec`（4 秒），走到 0 → 下一波 `spawning`（或 `boss_intro`）。**场上还有敌人也照样开始；清场不会缩短空档** |
| `boss_intro` Boss 登场 | 下一波是 Boss 波 | 无（立绘演出，逻辑暂停，可跳过） | 演出结束 → `spawning`（Boss 波） |
| `final` 最后一波 | 最后一波的刷怪窗口结束。Boss 关要等 Boss 被击败，这一波才算打完 | 所有操作；没有叫波 | 普通关：场上敌人清空且守护点生命 > 0 → `victory`。Boss 关：Boss 已被击败，并且场上其他敌人也清空 |
| `victory` 胜利 | 见第 5 节 | 无 | 进入结算界面 |
| `defeat` 失败 | 见第 5 节 | 无 | 失败界面：从当前波重来，或整关重打 |

波与波之间只有这一个 `intermission` 状态。旧版的 `waiting` 状态（出完后等 8 到 15 秒，清场才进空档）和「清场缩短空档」的规则都删掉了，原因见 4.2。换符卡使只能在 `deploy` 和 `intermission` 里做，换人清空能量（spell_cards.md 第 1 节）。

另有「逻辑暂停原因」集合，和上面的状态并行，只要集合非空逻辑就暂停：`spell_cutin`（符卡立绘）、`boss_cutin`（Boss 换阶段立绘）、`buff_select`（强化三选一）、`menu`（暂停菜单）、`tutorial_hold`（教学等待玩家操作）。

### 4.2 波次时间轴（D-03 已定）

回应 PR #9 的 DI-03、DI-04。战斗策划和关卡策划已对齐这一版，关卡策划在 PR #5 按同一版写。数值策划 PR #8 的 `stats.json` → `waves`（`advance_mode = spawn_window`、`spawn_window_sec`、`gap_sec`、`deploy_time_sec`）也是这个口径。

**「每波约 20 秒」的意思**：从这一波开始算 20 秒刷怪窗口（`battle_flow.spawn_window_sec`；关卡里是每波的 `duration_sec`）。第一只在窗口开始时出生，其余按数量摊在这 20 秒里。它不是「出怪 + 清怪」的总时长，也不是「第一只到最后一只」刚好 20 秒，更不是每个敌人走路的时间。

**开局**：

1. 关卡载入 → `deploy` 布阵期，倒计时 10 秒（`battle_flow.deploy_time_sec`）。玩家可以点「开始」提前结束。
2. 倒计时结束的同一刻第 1 波开始，第一只敌人马上出生。第 1 波前**没有**另外的 4 秒（`battle_flow.first_wave_delay_sec` = 0；关卡里 `waves[0].delay_sec` = 0）。
3. 序章开 `deploy_wait_for_player: true`：玩家放下第一个角色之前，倒计时停在 10 秒不走（对应 PR #2 `tut.prologue_01.004`「玩家放好之前不出怪」）。放下以后才开始倒数。

**波与波之间**：

1. 这一波的 20 秒窗口走完 → 进入 `intermission` 空档，固定 4 秒（`battle_flow.intermission_sec`；关卡里是下一波的 `delay_sec`）。没有 3 到 5 秒的浮动。空档从窗口结束起算（`gap_starts_at` = `spawn_window_end`），不是从最后一只出生起算。
2. 空档只按时间走：清场**不会**缩短它（`battle_flow.intermission_shortened_by_clear` = false），4 秒走到 0，下一波开始，**不管场上有没有清空**。上一波没打完的敌人继续留在场上，所以波次重叠是常态，不是只有叫波才重叠。
3. 下一波是 Boss 波时，先进 `boss_intro`，演出结束再开始。
4. 清波奖励 `economy.wave_clear_bonus` 在这一波进入空档时发（`battle_flow.wave_clear_bonus_at = intermission_start`），不等这一波的敌人全部离场。

**叫下一波**：

1. 在 `deploy`、`spawning`、`intermission` 里都可以叫（布阵期的按钮叫「开始」）。最后一波没有「下一波」，不显示按钮。
2. 在 `spawning` 里叫波：跳过这一波剩下的刷怪窗口和空档，下一波立刻开始。**这一波还没出生的敌人不会被丢掉**，仍按原来的时间表出生，和下一波叠在一起（`battle_flow.early_call_keeps_current_wave_spawns` = true，`early_call_drops_unspawned` = false）。所以叫波是「拿灵力、扛更密的怪」的冒险选择，不能用来跳过敌人。
3. 在 `intermission` 里叫波：跳过剩下的空档，下一波立刻开始。
4. 在 `deploy` 里点「开始」：跳过剩下的布阵倒计时。
5. 叫波奖励 = `min(economy.early_call_reward_cap, floor(本来到下一波开始还剩的秒数 × economy.early_call_reward_per_sec))`。上限见 `economy.early_call_reward_cap`，不在本文写数字。布阵期提前开始仍按 `economy.early_start_reward_per_sec`。用户 2026-10-02 定（D-18）：叫波要做。刷怪窗口里可以叫下一波，这一波还没出生的敌人按原时间表照常出生，和下一波叠在一起。T-00 原型这一轮可以后补实现，规则以本节为准。

**和旧稿的差别**：旧稿在布阵 10 秒之后还要再等 4 秒才出第一只。已定去掉这 4 秒：布阵结束，第一只马上出生。PR #5 的 `waves[0].delay_sec` 是 0。

### 4.3 节奏目标（已拍板，2026-09-27）

- 每波刷怪窗口 20 秒，窗口结束后固定空 4 秒。计时口径见 4.2。
- 序章可以少于 5 波。其余关卡 10 到 20 波。MVP 关卡多用 10 到 12 波。
- 时长按波数估：每波约 20 + 4 = 24 秒，10 波约 4 分钟，20 波约 8 分钟，再加开局布阵和最后一波的清场时间。叫波会更快。
- 举例（关卡策划 [PR #5](https://github.com/XYN159/Touhou-forgotten-defense/pull/5)）：序章 3 关，分别是 3、4、10 波；第一章 4 关，分别是 10、11、12、15 波，第 4 关 `ch1_04` 是冰之残影 Boss 关。15 波落在 10 到 20 波里。
- 序章前两关没有三选一。序章第 3 关开始教三选一。按上面的举例，第 3 关是 10 波，第 5 波出完、进入空档时弹出一次；第 10 波是这一关的最后一波，不再弹。

## 5. 守护点、胜负

### 5.1 守护点

- 守护点有生命值 `stats.json` → `guard.max_hp`【数值·PR #8】。叙事上叫守护点的「颜色」（PR #2 术语表，系统名待系统策划定）。
- 每个敌人到达守护点扣它的漏怪伤害：普通敌人是 `enemies.<id>.leak_damage`，Boss 是 `bosses.<id>.leak_damage`（冰之残影 = `bosses.boss_cirno.leak_damage`，每走到一次扣一次）【数值·PR #8】。回应 DI-07：Boss 只在 `bosses` 段，不在 `enemies` 段。
- 慧音的「隐史」给守护点加护盾层，每层抵消一次漏怪（见 characters.md）。
- **报警**：任一敌人进入最后 2 行（`row ≥ 10`）时，守护点闪红光并播报警音【框架】。报警音 2 秒（真实时间）内最多响一次；只要最后 2 行有敌人，守护点就持续红光脉冲【草案默认值】。
- **扣血反馈**：守护点每次扣血，屏幕边缘泛红 0.4 秒【框架】；0.4 秒内再次扣血就重置计时，不叠加亮度。

### 5.2 胜负【战斗策划决定 5】

- **失败**：守护点生命 ≤ 0（制作人说的「基地」就是这里的守护点）。第 ⑩ 步扣到 0 以后，第 ⑪ 步立刻判负，同一 tick 其他事件不再有意义。
- **普通关胜利**：最后一波已经打完，场上没有任何敌人（被消灭或漏掉都算离场），并且守护点生命 > 0。
- 同一 tick 既满足胜利又满足失败时，判失败。
- **Boss 关**（已拍板，2026-09-27）：最后一波要等 Boss 被击败才算打完。Boss 走到守护点时扣 `leak_damage`，然后回到裂缝重新走，不离场。见 enemies_and_bosses.md。
- **输了之后**：可以选「从当前波重来」或整关重打（`retry.on_defeat`）。从当前波重来时，恢复到该波开始那一刻的快照（`restart_wave_restore` = `wave_start_snapshot`）。回应 DI-05，快照内容固定如下（`retry.snapshot_restores` / `snapshot_does_not_restore`）：

| 恢复 | 不恢复 |
| --- | --- |
| 守护点生命、灵力、已放角色（格子、等级）、强化层数、符卡能量、当前符卡使、场上残存的敌人（含 Boss 的血量、阶段、位置）、地形、波次计时、随机数状态 | 连击数（归 0）、已发现的联动（发现过就不收回）、教学进度 |

  「这一波开始那一刻」= 这一波第一只出生前。因为不等清场，上一波留下的敌人也在快照里。Boss 关从 Boss 波重来时，Boss 回到这一波开始时的血量和阶段（一般是满血第 1 阶段）。

## 6. 操作（竖屏单手）

### 6.1 放置

1. 只能放在地图里标成 `.` 的预定槽位上（`placement.allowed_cell_mark`）。点一个空的 `.` 格 → 底部弹出角色栏，显示本关带来的角色头像和费用。灵力够的头像亮起（对应 PR #2「头像亮起时才能放置角色」）。别的格子不能放。路线格标成 `P`。
2. 点头像 → 立刻放置，扣灵力，播放 0.25 秒落地动画。放置后 0.3 秒【草案默认值】开始攻击。
3. 点别处取消。
4. 同一角色最多放 3 个（已拍板，2026-09-27）。每个角色的上限和递增比例是 `characters.<id>.max_copies`、`characters.<id>.copy_cost_increase_ratio`【数值·PR #8】，`rules.json` 的 `placement.max_copies_per_character` 只是缺省值。多放一个怎么涨价，公式以 PR #8 为准。
5. 美铃是阻挡型，也放在 `.` 格，但必须紧贴路线，挡住相邻路线格上的敌人（用户 2026-10-02 定，D-19；见 characters.md）。不能放在路线格 `P` 上。

### 6.2 已放置的角色

点已放置的角色：显示射程圈，并弹出小面板「升级（费用）」「卖出（返还）」。在 `deploy` 和 `intermission` 里，面板上还有「设为符卡使」（见 spell_cards.md）。`spawning` 里没有这一项。

- 升级：每个角色从 1 级升到 3 级，一共升 2 次（`character_levels.max_level` = 3，已和数值策划对齐）。升级费用是 `characters.<id>.upgrade_costs`，每级攻击倍率是 `characters.<id>.level_attack_mult`【数值·PR #8】。每级外观和特效变化见 characters.md。
- 卖出：返还已花费灵力 × `characters.<id>.sell_refund_ratio`【数值·PR #8】。波次中也能卖。
- 被冻住的角色（`st_unit_frozen`）不能升级或卖出，也不能连点提前破冰（用户 2026-10-02 定，D-05）。冻结走完来源给的时长才结束。点击冰块不产生裂纹，也不缩短时长。

## 7. 边界情况汇总

| 情况 | 处理 |
| --- | --- |
| 敌人刚出生 | 出生状态 0.3 秒【草案默认值】：不移动、不可被选为目标，防止还没看见就被秒。 |
| 射程内没有敌人 | 冷却停在「就绪」，敌人一进射程立即攻击。 |
| 目标在弹体飞行中死亡 | 追踪弹在 `retarget_radius_cells` 内换最近的新目标；没有就直线飞完寿命后消失。非追踪弹继续直飞，可以打中路过的敌人。 |
| 攻击者在弹体飞行中被卖掉 | 已发出的弹体照常结算，仍算那个角色的攻击（联动照样生效）。弹体生成时记下 `attacker_character_id`。 |
| 立绘演出期间有输入 | 点击只用来跳过演出，不执行放置等指令。 |
| 两个立绘演出在同一 tick 被触发 | 按触发顺序排队播放：玩家符卡（第 ① 步）在前，Boss 换阶段（第 ⑧ 步）在后。 |
| 慢动作期间又满足慢动作条件 | 不重新触发（有 8 秒冷却）。 |
| 叫波时场上有 Boss | 允许，奖励照算。 |
| 刷怪窗口里叫波 | 这一波没出生的敌人不丢，按原时间表照常出生，下一波立刻开始叠上来。奖励按「本来到下一波开始还剩的秒数」算。 |
| 空档里场上已经清空 | 空档不缩短，照样走完 4 秒（想早点开始就叫波）。 |
| 2 倍速下的立绘演出和强化选择 | 不受倍速影响（按真实时间播放）。 |
