# 核心规则：格子、时间、局内流程、操作

> 状态：草案（战斗策划）。本文件是程序实现战斗循环的主依据。
> 数字标记：**【框架】** = 制作人已验收的框架，照做；**【草案默认值】** = 战斗策划给的默认值，可调；**【占位·数值】** = 属于数值策划的字段，占位，待数值策划确认。
> 对应配置：`data/balance/combat/rules.json`（规则和手感参数）、`data/balance/combat/stats.json`（数值占位）。字段说明见 [data_reference.md](data_reference.md)。

## 1. 棋盘和坐标

### 1.1 格子

- 棋盘是 **7 列 × 12 行**【框架】。
- 坐标写成 `[col, row]`，原点在**左上角**：`col` 从左到右是 0–6，`row` 从上到下是 0–11。
- 残影从上方（小 `row`）出现，沿路线走向下方的守护点（大 `row`）。
- 所有距离、射程、速度都用「格」作单位。1 格 = 一个格子的边长。
- 位置用浮点数表示，格子 `[c, r]` 的中心点是 `(c + 0.5, r + 0.5)`。
- 射程判定用**圆形**：角色格子中心到敌人当前位置的直线距离 ≤ 射程格数，就算在射程内。

### 1.2 格子类型

格子类型由关卡数据给出（关卡策划负责），战斗只认下面几种：

| 类型 | 含义 | 能放角色 | 敌人能走 |
| --- | --- | --- | --- |
| `path` | 路线格 | 否 | 是 |
| `placeable` | 可放置格（教学里叫「发光的格子」） | 是 | 否 |
| `blocked` | 装饰或障碍（湖面、树） | 否 | 否 |
| `spawn` | 裂缝（出怪点），同时也是路线的第一格 | 否 | 是 |
| `guard` | 守护点所在格，是路线的最后一格 | 否 | 是（到达即结算） |

地形（冰面、浓雾、冰柱等）是叠在格子上的「地形效果」，不改变格子类型。对接方式见 [terrain_and_map.md](terrain_and_map.md)。

### 1.3 画面尺寸（需要确认）

- 工程逻辑分辨率是 1080×1920（`project.godot`）。如果 7 列铺满宽度，每格约 154 像素，12 行就要约 1851 像素，只剩约 70 像素给界面，放不下底部的符卡按钮和角色栏。
- 【草案默认值】每格 128 像素，棋盘 896×1536，左右各留 92 像素，顶部留 140 像素（波次、守护点生命、Boss 血条），底部留约 244 像素（灵力、符卡按钮、倍速、叫波）。更高的手机屏幕（`expand` 模式）多出来的高度加给底部栏。
- 这是界面问题，最终由程序和制作人在真机上确认。配置里的字段是 `grid.cell_size_px` 和 `grid.board_offset_px`。

### 1.4 路线和「路程」

- 关卡数据给出每条路线的**格子序列**（从 `spawn` 到 `guard`，相邻两格必须上下或左右相邻）。
- 敌人沿「格子中心连线」移动。敌人的位置用 `path_progress`（已走过的格数，浮点）表示，0 = 裂缝格中心，`path_length` = 守护点格中心。
- **离守护点的路程** = `path_length - path_progress`。选敌、危急判定、紫的隙间换位都用这个值。
- 敌人所在的「行」= 它当前位置向下取整得到的 `row`。「最后 N 行」= `row ≥ 12 - N`。
- 一张地图可以有多条路线（多个裂缝）。比较不同路线上的敌人时，只比较「离守护点的路程」。

## 2. 时间和 tick

### 2.1 固定 60Hz 逻辑

- 战斗逻辑以**固定 60Hz** 的 tick 运行，每 tick 逻辑时长 `dt = 1/60 秒`【草案默认值，来自战斗策划决定 1】。
- 演出（闪白、飘字、震屏、光点）不影响逻辑结果。例外只有两个：**慢动作**（逻辑变慢）和**立绘演出**（逻辑暂停）。
- 所有逻辑用的随机数（暴击、冻结几率、强化抽选）来自**每局一个种子**的随机数生成器，方便测试复现。

### 2.2 时间倍率怎么实现（给程序）

不要用 `Engine.time_scale` 驱动逻辑：它会改变每个物理帧的 `delta`，导致「每 tick 固定 1/60 秒」失效。建议做法：

1. 战斗自己维护一个累加器 `logic_accumulator`。
2. 每个物理帧：`logic_accumulator += 真实帧时长 × 总倍率`。
3. `总倍率 = 倍速（1 或 2） × 慢动作倍率（平时 1，慢动作 0.3） × 暂停（立绘演出、强化三选一、菜单时为 0）`。
4. 当 `logic_accumulator ≥ 1/60` 时执行一次 tick 并减去 1/60，最多连续执行 `tick.max_ticks_per_frame = 4` 次，防止卡顿后雪崩。
5. 演出层（动画、粒子、飘字）用真实时间 × 倍速播放，不跟随慢动作以外的逻辑暂停。

所以 2 倍速 = 每帧跑 2 个 tick；慢动作 + 2 倍速 = 2 × 0.3 = 0.6 倍【框架：慢动作倍率与 2 倍速相乘】。

### 2.3 每 tick 结算顺序【战斗策划决定 1】

每个 tick 严格按下面 12 步执行。同一步里有多个对象时，按「生成顺序（实例 ID 从小到大）」处理，保证结果可复现。

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| ① | 处理玩家指令 | 放置、升级、卖出、释放符卡、叫下一波、开关自动释放。指令在输入时进队列，这一步统一执行。自动释放符卡的判定也在这一步。 |
| ② | 波次计时与刷怪 | 推进波次状态机（第 4 节），把到时间的敌人放到裂缝格。新出生的敌人本 tick 不移动。 |
| ③ | 状态计时更新和到期移除 | 所有敌人和角色身上的状态时长减 `dt`，到期的移除并触发 `on_end_apply`（比如冻结结束给冻结免疫）。持续伤害（灼烧）的跳伤也在这一步产生「命中请求」，放到第 ⑧ 步结算。 |
| ④ | 地形效果计算 | 地形计时、生成和消失；区域类地形（结界、火焰地面）检查敌人进出，挂上或移除状态；算出每个敌人本 tick 所在格子的移动倍率。 |
| ⑤ | 敌人移动 | 按第 3.2 节公式推进 `path_progress`。走到 `path_length` 的敌人标记为「到达中」（`reaching`），但**本 tick 仍然可以被攻击**，第 ⑩ 步才结算。 |
| ⑥ | 角色选敌、攻击冷却 | 冷却减 `dt`；冷却好且射程内有目标就攻击：即时命中类（魔理沙直线、紫的隙间、近战）直接生成「命中请求」；弹体类生成弹体。自动技能（灵梦结界、琪露诺冻结、紫的隙间换位）也在这一步按冷却触发。 |
| ⑦ | 弹体移动与命中检测 | 移动弹体，检测碰撞，碰到就生成「命中请求」。直线类攻击在这一步检查冰柱遮挡。 |
| ⑧ | 逐次命中结算 | 按生成顺序逐个执行伤害流水线（见 [damage_and_status.md](damage_and_status.md)）。一个敌人血量归零后，本 tick 后续打到它的命中请求作废（弹体按各自规则转向或消失）。 |
| ⑨ | 死亡处理 | 发灵力、记连击、加符卡能量（击杀部分）、触发死亡相关效果（强化「青蛙冰雕」、忘的「登记」等）。 |
| ⑩ | 到达守护点结算 | 对仍处于「到达中」且未死亡的敌人：守护点扣「漏怪伤害」，敌人移除（Boss 按自己的规则折返）。 |
| ⑪ | 胜负判定 | 见第 5 节。 |
| ⑫ | 反馈事件入队 | 把本 tick 产生的所有反馈事件（闪白、飘字、光点、震屏、连击、报警等）交给演出队列。演出层按 [feedback.md](feedback.md) 的节流和上限规则播放。 |

**这个顺序带来的效果（程序要保证）**：

- 敌人在第 ⑤ 步踩进守护点，如果第 ⑥–⑧ 步被打死，就不扣守护点的血。这是「险胜」手感的来源。
- 同一 tick 里先结算伤害（⑧），后结算死亡（⑨），再结算漏怪（⑩），最后判胜负（⑪）。

## 3. 敌人移动

### 3.1 基础速度

每种敌人的 `move_speed_cells_per_sec`（格/秒）在 `stats.json` 的 `enemies` 里：普通残影 1.0，快残影 2.0，硬残影 0.7，Boss 琪露诺 0.5。快残影的 2.0 已确认，其余移速仍是占位。

### 3.2 每 tick 的移动公式

1. 如果敌人身上有任何「硬停止」状态（`st_freeze`、`st_time_stop`、`st_hold`、`st_gap_daze`），本 tick 速度为 0。
2. 否则：
   - `减速倍率 = 1 - 最强的一个 st_slow 的强度`（减速不叠加，只取最强）。
   - `地形倍率 =` 敌人当前所在格子上「移动类地形」的倍率（冰面 1.5；没有地形就是 1.0；多个移动类地形重叠时取优先级最高的一个）。
   - `总倍率 = 减速倍率 × 地形倍率`，再限制在 `[下限, 2.0]` 之间。下限：普通敌人 0.3【框架：移动速度总倍率下限 30%】，Boss 0.5【草案默认值】。
3. `path_progress += 基础速度 × 总倍率 × dt`。

例子：快残影（`stats.json` 里 2.0 格/秒）被琪露诺减速 35%，又踩在冰面上：2.0 × 0.65 × 1.5 = 1.95 格/秒。普通残影同时吃到 70% 减速：1.0 × 0.3 = 0.3（刚好在下限上）。

### 3.3 击退

- 击退 = 把 `path_progress` 往回减，默认每次命中 0.1 格【框架】。
- 同一个敌人 0.25 秒内只吃一次普通击退【草案默认值】，防止高攻速角色把敌人钉死。技能标明的大击退（美铃重击、彩光乱舞）不受这个冷却限制。
- 硬残影有 50% 击退抗性（击退距离 × 0.5）。
- 冻结、时停中的敌人和 Boss 不被击退。
- 击退不会把 `path_progress` 减到 0 以下。
- 「到达中」的敌人被击退到 `path_length` 以下时，取消「到达中」标记。

## 4. 局内状态机和波次

### 4.1 局内状态

| 状态 | 进入条件 | 期间允许的操作 | 退出条件 |
| --- | --- | --- | --- |
| `deploy` 布阵期 | 关卡载入完成 | 放置、升级、卖出、「开始」按钮 | 倒计时 10 秒【框架：约 10 秒】结束，或玩家点「开始」 |
| `spawning` 波次中（出怪） | 某一波开始 | 所有操作；叫波按钮灰掉 | 这一波的敌人全部出完 → `waiting` |
| `waiting` 等待下一波 | 当前波出完 | 所有操作；可以叫下一波 | 下一波倒计时到 0 → `spawning`；场上敌人清空 → `intermission` |
| `intermission` 空档 | 当前波出完且场上没有敌人 | 所有操作；可以叫下一波；可能弹出强化三选一 | 空档倒计时到 0 → `spawning`（或 `boss_intro`） |
| `boss_intro` Boss 登场 | 下一波是 Boss 波 | 无（立绘演出，逻辑暂停，可跳过） | 演出结束 → `spawning`（Boss 波） |
| `final` 最后一波 | 最后一波出完 | 所有操作；没有叫波 | 场上敌人清空 → `victory` |
| `victory` 胜利 | 见第 5 节 | 无 | 进入结算界面 |
| `defeat` 失败 | 见第 5 节 | 无 | 进入失败界面（重开） |

另有「逻辑暂停原因」集合，和上面的状态并行，只要集合非空逻辑就暂停：`spell_cutin`（符卡立绘）、`boss_cutin`（Boss 换阶段立绘）、`buff_select`（强化三选一）、`menu`（暂停菜单）、`tutorial_hold`（教学等待玩家操作）。

### 4.2 波次计时规则

每一波在关卡数据里有 `next_wave_delay_sec`（关卡策划填，推荐 8–15 秒），含义是「从这一波**出完最后一只**起，到下一波开始的时间」。

1. 这一波出完 → 进入 `waiting`，开始倒计时 `next_wave_delay_sec`。
2. 倒计时期间场上敌人全部消灭 → 进入 `intermission`，倒计时改为 `min(剩余时间, 4 秒)`【框架：波次之间 3 到 5 秒空档；草案默认 4 秒，关卡可以在 3–5 之间覆盖】。
3. 倒计时到 0 → 下一波开始。如果下一波是 Boss 波，先进 `boss_intro`。
4. 叫下一波：在 `deploy`、`waiting`、`intermission` 三种状态下可以点「叫下一波」（布阵期对应按钮叫「开始」）。立即开始下一波，奖励 `floor(剩余倒计时秒数 × 每秒奖励)` 灵力【框架】。每秒奖励：叫波 2、提前开始 1【占位·数值】。
5. 波次允许重叠：叫波后上一波没打完的敌人继续留在场上。
6. 最后一波没有「下一波」，所以不显示叫波按钮。

### 4.3 节奏目标【框架】

- 一关 3 到 5 分钟。开局约 10 秒布阵；波次之间 3 到 5 秒空档；最后几波或 Boss 登场是高潮。
- 给关卡策划的换算参考：若一关 8 波、每波出怪 10–15 秒、`next_wave_delay_sec` 10 秒，不叫波时约 3.5 分钟；积极叫波能压到 3 分钟以内。
- 教学关可以用关卡开关 `deploy_wait_for_player: true` 让布阵倒计时暂停，直到玩家完成放置（对应 PR #2 `tut.prologue.004`「玩家完成放置前不出怪」）。

## 5. 守护点、胜负

### 5.1 守护点

- 守护点有生命值 `guard.max_hp`，占位 20【占位·数值】。叙事上叫守护点的「颜色」（PR #2 术语表，系统名待系统策划定）。
- 每个敌人到达守护点扣它的 `leak_damage`：普通 1、快 1、硬 2、Boss 每次 5【占位·数值】。
- 慧音的「隐史」给守护点加护盾层，每层抵消一次漏怪（见 characters.md）。
- **报警**：任一敌人进入最后 2 行（`row ≥ 10`）时，守护点闪红光并播报警音【框架】。报警音 2 秒（真实时间）内最多响一次；只要最后 2 行有敌人，守护点就持续红光脉冲【草案默认值】。
- **扣血反馈**：守护点每次扣血，屏幕边缘泛红 0.4 秒【框架】；0.4 秒内再次扣血就重置计时，不叠加亮度。

### 5.2 胜负【战斗策划决定 5】

- **失败**：守护点生命 ≤ 0。第 ⑩ 步扣到 0 以后，第 ⑪ 步立刻判负，同一 tick 其他事件不再有意义。
- **胜利**：最后一波已经出完，场上没有任何敌人（被消灭或漏掉都算离场），并且守护点生命 > 0。
- 同一 tick 既满足胜利又满足失败时，判失败。
- **Boss 关**（已拍板，2026-09-27）：Boss 走到守护点时扣 `leak_damage`，然后回到裂缝重新走，不离场。必须打倒 Boss 才算胜利。见 enemies_and_bosses.md。

## 6. 操作（竖屏单手）

### 6.1 放置

1. 点一个空的可放置格 → 底部弹出角色栏，显示本关带来的角色头像和费用。灵力够的头像亮起（对应 PR #2「头像亮起时才能放置角色」）。
2. 点头像 → 立刻放置，扣灵力，播放 0.25 秒落地动画。放置后 0.3 秒【草案默认值】开始攻击。
3. 点别处取消。
4. 同一角色最多放 3 个（`placement.max_copies_per_character`，已拍板，2026-09-27）。第 2、第 3 个的费用按上一个再乘 `stats.json` 的 `copy_cost_increase_ratio`【占位·数值】。

### 6.2 已放置的角色

点已放置的角色：显示射程圈，并弹出小面板「升级（费用）」「卖出（返还）」。在 `deploy` 和 `intermission` 里，面板上还有「设为符卡使」（见 spell_cards.md）。`spawning` 和 `waiting` 里没有这一项。

- 升级：每个角色从 1 级升到 3 级，一共升 2 次（`character_levels.max_level` = 3，已和数值策划对齐）。升级费用和每级攻击倍率在 `stats.json`，占位。每级外观和特效变化见 characters.md。
- 卖出：返还已花费灵力 × 70%【占位·数值】。波次中也能卖。
- 被冻住的角色（`st_unit_frozen`）不能升级或卖出，但可以连点 3 下提前敲碎冰块【草案默认值】。

### 6.3 界面按钮

| 按钮 | 位置 | 规则 |
| --- | --- | --- |
| 符卡按钮 | 底部正中，最大 | 能量满时发光并脉冲【框架】。点击释放当前符卡使的默认符卡。符卡使规则见 spell_cards.md（方案 A+，已拍板）。 |
| 自动释放开关 | 符卡按钮右上角的小开关 | 默认关。规则见 spell_cards.md。 |
| 倍速 | 底部右侧 | 1×/2× 切换【框架】，记住上次选择。 |
| 叫下一波 / 开始 | 底部右侧、倍速上方 | 显示预计奖励，比如「+12」。 |
| 暂停 | 左上角 | 暂停菜单。 |

## 7. 边界情况汇总

| 情况 | 处理 |
| --- | --- |
| 敌人刚出生 | 出生状态 0.3 秒【草案默认值】：不移动、不可被选为目标，防止还没看见就被秒。 |
| 射程内没有敌人 | 冷却停在「就绪」，敌人一进射程立即攻击。 |
| 目标在弹体飞行中死亡 | 追踪弹在 `retarget_radius_cells` 内换最近的新目标；没有就直线飞完寿命后消失。非追踪弹继续直飞，可以打中路过的敌人。 |
