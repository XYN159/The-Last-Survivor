# 对话样本：序章与第一章

> 东方 Project 二次创作。本文件是可读版剧本，内容与文本表 [`data/text/dialogue_zh.csv`](../../../data/text/dialogue_zh.csv) 逐行一致。**改台词时以 CSV 为准，并同步本文件。**
> 角色名、章节名、符卡名在 [`data/text/names_zh.csv`](../../../data/text/names_zh.csv)。

## 文本表格式

仓库里原本没有文本表或本地化格式（`data/` 下只有旧玩法的 `data/balance/starting_balance.json`）。因为本工程是 Godot 4，文本表直接采用 **Godot 的 CSV 翻译格式**，以后程序可以直接用 `tr("dlg.prologue.pre.001")` 取文本，将来加英文或日文只需要加一列。

### dialogue_zh.csv

| 列 | 含义 | Godot 如何处理 |
| --- | --- | --- |
| `key` | 文本 key，全表唯一 | 第一列固定作为翻译 key |
| `_speaker_key` | 说话人的角色 key，如 `char.reimu`；教学提示留空 | 列名以下划线开头，Godot 导入时**忽略** |
| `zh_CN` | 简体中文正文（即需求里的 `text` 列） | 作为 `zh_CN` 语言的翻译 |
| `_note` | 触发条件、演出说明、给程序和关卡的备注 | 以下划线开头，导入时忽略 |

> 需求原本建议的列名是 `key,speaker_key,text,note`。这里只是把 `text` 写成语言代码 `zh_CN`，并给 `speaker_key`、`note` 加了下划线前缀，列的顺序和含义不变。这样 Godot 导入时不会把 `speaker_key`、`note` 误当成语言、报“无效语言代码”的错误。

### names_zh.csv

| 列 | 含义 |
| --- | --- |
| `key` | 文本 key |
| `zh_CN` | 简体中文 |
| `_note` | 备注（原名、待定项等），导入时忽略 |

### 格式约定

- UTF-8（无 BOM），换行 LF，逗号分隔。正文只用全角标点，所以目前不需要引号转义。
- 正文里不要写反斜杠 `\`（Godot 默认会对译文做转义处理）。
- 正文单句建议不超过 40 字（当前最长 25 字）。
- 正文只使用当前字体子集 `assets/fonts/NotoSansSC-Regular.ttf` 里有的字形。已核对：本表所有正文字符都在字体里。**注意：字体子集里没有日文假名**，所以 `_note` 里的符卡原名（如 恋符「マスタースパーク」）只能留在备注里，不能直接显示在游戏中。如果以后想在游戏里显示原名，需要程序扩大字体子集。
- Godot 导入 CSV 时会在同目录生成 `*.translation` 文件，已被仓库的 `.gitignore` 忽略；生成的 `*.csv.import` 按 Godot 惯例可以提交。
- 程序接入时，需要把生成的翻译加入 `project.godot` 的“本地化 → 翻译”列表（这一步属于程序工作，本 PR 不改 `project.godot`）。

## key 规则

| 类型 | 格式 | 例子 |
| --- | --- | --- |
| 关卡对话 | `dlg.<章节>.<阶段>.<三位序号>` | `dlg.prologue.pre.001` |
| 教学提示 | `tut.<章节>.<三位序号>` | `tut.prologue.004` |
| 角色气泡名 | `char.<角色id>.name` | `char.reimu.name` → 灵梦 |
| 角色全名 | `char.<角色id>.fullname` | `char.reimu.fullname` → 博丽灵梦 |
| 章节名 | `stage.<章节>.name` | `stage.ch01.name` → 第一章 雾之湖 |
| 符卡名 | `spell.<角色id>.<符卡id>.name` | `spell.reimu.fantasy_seal.name` → 灵符「梦想封印」 |
| 游戏标题等 | `game.<id>` | `game.fanwork_notice` → 东方 Project 二次创作 |

- **章节**：`prologue`（序章）、`ch01`～`ch05`（第一至五章）、`final`（终章）。
- **阶段**：`pre`（关前）、`mid`（关中触发）、`duel`（符卡决斗中）、`post`（关后）。序章没有 `duel`。
- **序号**：三位数，按播放顺序递增。已接入的 key 不要改名、不要重排；以后插入台词时用新的序号追加，并在 `_note` 写明插在哪一句之后，实际播放顺序以关卡脚本为准。
- **角色 id**：`reimu`、`marisa`、`cirno`、`daiyousei`、`meiling`、`sakuya`、`remilia`、`keine`、`mokou`、`aya`、`sanae`、`yukari`、`wasure`（落野忘，简称忘；key 不改）。
- **说话人**：对话行的 `_speaker_key` 是 `char.<角色id>`，界面显示名取 `char.<角色id>.name`。
- **播放顺序**：同一个触发点下的连续台词，按 key 序号依次播放。教学提示（`tut.*`）和对话交错出现时，以本文件里的排列顺序为准。
- **触发条件**：暂时写在 `_note` 里，给关卡策划和程序参考。以后如果做了关卡脚本数据（例如每关一个 JSON），建议把触发条件搬过去，文本表只留文本。
- **普通残影没有台词。**
